# Архитектура Phantom

Phantom — Kotlin/Compose-клиент с настоящим Xray-core. Основной процесс содержит UI,
VpnService и один Go runtime libXray. Отдельный процесс `:probe` содержит независимый
Go runtime для проверки серверов без остановки активного VPN. HEV написан на C и
не добавляет второй Go runtime в основной процесс.

```text
Android-приложения
  → VpnService TUN (IPv4; IPv6 по настройке)
  → hev-socks5-tunnel 2.19.3 (TCP + SOCKS UDP associate)
  → внутренний SOCKS 127.0.0.1:10990
  → маршрутизация / DNS / балансировщики Xray-core 26.11.9
  → Proxy / Direct / Block
```

Адаптер HEV выбран за dual stack, TCP/UDP, Android JNI, счётчики пакетов/байтов и
простое управление заимствованным TUN fd. Передаваемый fd дублируется и закрывается
Phantom после остановки HEV. Нативный Xray TUN не предлагается вторым переключателем:
это иной backend, требующий отдельной проверки, а не настройка оформления.

## Защита от петель и DNS

`registerDialerController` вызывает `VpnService.protect()` для исходящих сокетов Go.
Приложение не исключает собственный UID из VPN: это позволяет проверять именно TUN.
Защищённый процессный resolver libXray получает DNS физической сети для начального
разрешения адресов серверов. Это намеренное исключение для bootstrap.

DNS приложений направлен Android на 10.66.0.2. Пакеты идут через TUN → HEV → SOCKS
UDP → выделенное правило → DNS outbound Xray. Для URI используется настраиваемый
DNS/DoH; JSON сохраняет собственный `dns`, его теги и правила провайдера. Пользователь
видит это различие в настройках. Android Private DNS и фактические утечки нужно
дополнительно проверять на телефоне; ECH и собственные DoH приложений ограничивают
доменные правила со sniffing.

IPv6 выключен по умолчанию. При отсутствии IPv6-адресов в Builder Android блокирует
эту семью для приложений VPN; `allowFamily(AF_INET6)` не вызывается. Включение добавляет
IPv6-адрес и маршрут `::/0`. Предпочтение семей DNS для URI настраивается отдельно.
Явные исключения приложений направляются Android напрямую по выбору пользователя.

## Состояние и жизненный цикл

`OFF → STARTING → TUNNEL → ONLINE`. ONLINE появляется после HTTPS-ответа через
`Network.socketFactory` именно VPN-сети и роста обоих счётчиков TUN. Неудачная
проверка оставляет статус «туннель работает, интернет не подтверждён».

VpnService — foreground service типа systemExempted, допустимого для настроенного
пользователем VPN. Уведомление содержит отключение. Сервис сериализует команды,
наблюдает физические сети без VPN, переподключается при смене сети/адресов, сохраняет
TUN как приёмник пакетов при перезапуске ядра и поддерживает START_STICKY. Постоянная
VPN и блокировка без VPN включаются пользователем в настройках Android. Постоянный
WakeLock не используется. Ограничения питания vivo требуют аппаратного теста.

Проверки HTTP выполняются процессом `:probe`. Для его исходящих сокетов fd передаётся
через Binder основному VpnService, который вызывает protect() и возвращает результат.
Так проверка другого сервера не подменяет текущий туннель. Пакеты Binder содержат одну
конфигурацию и настройки теста; URL подписки и каталог хранилища не передаются.

## Хранилище и задачи

Каталог — AES-256-GCM с ключом Android Keystore, AtomicFile, Mutex и StateFlow.
Данные находятся в noBackupFilesDir; cloud backup и перенос данных исключены.
URL подписок не включаются в экспорт JSON. Экспорт содержит ключи серверов и
выполняется только по действию пользователя через Android Storage Access Framework.

HTTP, разбор конфигураций, Keystore, дисковые операции, проверки и JNI работают
на Dispatchers.IO. UI получает неизменяемые снимки через StateFlow. Обновление
подписки атомарно сохраняет прежний рабочий список при неудаче. WorkManager проверяет
интервалы раз в час; Doze может отложить задачу. Трафик HEV измеряется по фактическому
интервалу и сохраняется каждые 10 секунд и при штатном отключении.

Сырые сообщения Xray и HEV не сохраняются: они могут содержать секреты. Журнал Phantom
содержит классифицированные события в памяти, максимум 300 строк; выбранный уровень
действительно фильтрует записи. История DNS не имитируется.

## Анимация

Canvas рисует белые символы с 11 уровнями затухания; массивы столбцов и Paint создаются
через remember. Часы читаются в draw-фазе. Частота ограничена примерно 24–30 кадрами/с.
Canvas присутствует только на главном экране при работающем TUN, RESUMED lifecycle,
включённом экране и разрешённых анимациях. Уход со страницы или выключение экрана
удаляет coroutine кадров. Режим ONLINE не подменяет факт запуска TUN.
