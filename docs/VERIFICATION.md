## Реальные сетевые запросы на Windows

Запущен официальный Xray 26.11.9 с конфигурациями после адаптации Phantom, отдельными
SOCKS-портами и принудительным направлением тестового HTTPS через proxy/balancer.
Проверялся `https://www.gstatic.com/generate_204`, TLS-проверка не отключалась.

Из 13 выбранных сочетаний протокол/транспорт/тип конфигурации **11 получили HTTP 204**:

- VLESS TCP Reality: одиночная конфигурация и балансировщик;
- VLESS WebSocket TLS: одиночная конфигурация и балансировщик;
- VLESS XHTTP Reality и XHTTP TLS;
- VLESS gRPC TLS и gRPC Reality;
- Trojan TCP TLS: одиночная конфигурация и балансировщик;
- Hysteria/Hysteria TLS.

Один выбранный Shadowsocks-узел достиг тайм-аута 9 секунд. Выбранный балансировщик
gRPC TLS не прошёл HTTPS-handshake. Балансировщик WS TLS успешно прошёл повторный
запрос после 3 секунд ожидания старта; исходный и повторный результаты сохранены отдельно. Это результаты конкретных
узлов и условий сети, а не доказательство отсутствия поддержки протокола. Автоматический
выбор конкретного outbound внутри составных профилей не инспектировался.
Подробные обезличенные измерения: `host-network-results.json`.

Первый запуск curl внутри песочницы завершался Schannel SEC_E_NO_CREDENTIALS ещё
до сетевого теста; итоговый запуск проведён вне этого ограничения. Приведены результаты
именно итогового запуска. **Windows SOCKS-тест не проверяет Android VpnService/HEV.**

## Что заблокировало Android-проверки

`adb devices -l` не обнаружил физический телефон. Установлены Android SDK 36,
эмуляторы 37.3.8 и 35.4.9, Google APIs x86_64 API 36. `emulator -accel-check`
сообщил: **Android Emulator hypervisor driver is not installed**.

Проверены программный CPU-режим с ANDROID_I_WANT_MY_TCG=yes, SwiftShader,
вариант без GPU/Vulkan и вариант без симулятора модема. Оба эмулятора аварийно
завершились до загрузки Android с кодом **0xC0000005 (-1073741819)**. В одном
запуске дополнительно получена ошибка modem socket: Input/output error.
Рабочее ADB-устройство не появилось. Изменение компонентов Hyper-V/драйверов Windows
и перезагрузка компьютера не выполнялись.

Поэтому не выполнены запуск UI, визуальная проверка Compose, JNI на Android,
Android Keystore runtime, реальный TUN-трафик, тесты DNS/IPv6/leaks, разрешения,
сворачивание/экран, Wi-Fi/mobile, плитка и always-on на устройстве.

## Подготовленный стенд

`AndroidIntegrationTest` и отдельный APK `trafficprobe` компилируются. Стенд проверяет:

1. Версию нативного core, преобразование Reality/gRPC/WS/XHTTP и отказ malformed URI.
2. Сохранение в Keystore/AES-GCM и перезагрузку каталога без plaintext-маркера.
3. С разрешением VPN и приватным локальным fixture: TUN, HTTPS из **другого UID**,
   рост IP-счётчиков, независимую проверку сервера при включённом VPN, повторный
   запуск адаптера/core и Block-правило.

Эти тесты **скомпилированы, но не запущены**. Без fixture третий тест будет skipped.
Команды установки/запуска — в README. Приватный fixture не входит в исходники/APK.

## Приёмка на vivo X300 / Android 17

- Установить ARM64 APK, проверить запуск, запрос/отказ разрешения VPN и уведомлений.
- Добавить URL, обновить; отдельно включить Happ JSON User-Agent и проверить 80 записей,
  составные профили, метаданные и сохранение после перезапуска.
- Проверить реальные HTTP GET/HEAD и ошибки серверов, смену узла и переподключение.
- Через браузер и другое приложение проверить HTTPS/UDP, внешний IP и увеличение
  счётчиков; отдельно проверить Direct/Block и allowlist/denylist приложений.
- Включить/выключить IPv6, проверить IPv4/IPv6 endpoints и DNS leak-тест при каждом
  режиме Android Private DNS; проверить домашнюю LAN согласно выбранному правилу.
- Переключить Wi-Fi/mobile, отключить сеть и вернуть её; проверить отсутствие обхода
  туннеля при ошибке. Для строгой блокировки включить системный lockdown.
- Свернуть Phantom, погасить экран на 15–30 минут, проверить работу другого приложения,
  затем вернуть Phantom. Убедиться, что vivo не останавливает foreground service.
- Проверить дождь: только домашний экран + TUN; остановка в настройках, фоне и при
  выключении дисплея; возвращение при живом VPN; отключение декоративных анимаций.
- Проверить SOCKS/HTTP auth и LAN-доступ, плитку, действие отключения, always-on,
  автоматическое обновление после Doze и отказ камеры/файлового выбора.

Только после этих проверок можно утверждать работоспособность на конкретном vivo.
