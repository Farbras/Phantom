# Phantom VPN и OverSecure 1.4.0

Сравнение выполнено 26 ноября 2026 года. Эталонный APK `com.oversecure.vpn`, versionCode 21, имеет SHA-256 `8ce990baf23b258638a2ee4201760fc8cebb5be56193abfd23c17066811c5c20`. Телефон Honor ELP‑NX9 работает на Android 15, API 35.

## Сравнение ответов подписки

На одном тестовом URL обычный GET с User-Agent Phantom вернул HTTP 200 и 75 URI в Base64. GET Happ и POST OverSecure вернули HTTP 200 и по 80 полных Xray JSON. После сопоставления по `remarks` все 80 имели одинаковые `outbounds`, `routing` и DNS. 44 объекта совпали полностью, у 36 различалось поле `meta`. Порядок отличался. Phantom по умолчанию использует POST для поддерживаемых доменов OverSecure. Явно заданные User-Agent и HWID продолжают использовать обычный запрос.

Содержимое POST зависит от серверного токена, доступности `/fetch` и поддержки криптографии платформой. Phantom запоминает успешный хост и ограничивает повтор запроса двумя известными адресами провайдера. Ответ сервера метаданных во время проверки называл тот же резервный адрес, что и APK. При недоступности платформенного X25519 или ChaCha20‑Poly1305 Phantom использует прежний HTTPS‑импорт.

## Различия реализации

- Для Phantom сохранены существующие управление IPv6, маршруты, локальные прокси и форматы профилей. Эталон объявляет маршрут IPv6 при каждом запуске. В Phantom он зависит от имеющегося переключателя IPv6.
- Phantom делает начальную HTTPS-проверку для своего состояния `ONLINE`, затем опрашивает `1.1.1.1` через SOCKS по расписанию. При переходе сети Phantom восстанавливает выбранную конфигурацию. У эталона в переходе есть отдельная предварительная TCP-проверка.
- Phantom использует рабочие профили, сохранённую задержку, региональную группу и профили `Auto` для выбора резерва. Лимит и интервалы совпадают с подтверждёнными значениями. Полный параллельный подбор и порядок случайных выборок эталона отличаются.
- Вместо частного метода `queryStats` сборки OverSecure Phantom читает счётчики открытого Xray через локальный SOCKS с временной аутентификацией. Импортированный JSON не управляет этим маршрутом или дескриптором TUN.
- Экраны Compose и строки интерфейса сохранены. В прежней справке остаются описания HEV и старой проверки `ONLINE`. Актуальная схема описана в `ARCHITECTURE.md`.

## Проверки на Honor

| Сценарий | Результат |
| --- | --- |
| Одинаковый профиль на одном Wi‑Fi | Оба клиента подключили «Испания \| WS VPN#2», подняли `tun0` с `26.26.26.1/24` и получили HTTP 204 из отдельного приложения с другим UID. Совпадение исходных outbounds проверено по двум серверным ответам. |
| Свёрнутое приложение и выключенный экран | У обоих клиентов TUN сохранялся при уходе в фон и при состоянии телефона `Dozing`. Независимый HTTP-запрос в фоне прошёл. Проверка сна заняла несколько секунд. |
| Недоступный узел и резерв | Phantom поднял TUN на управляемом тестовом профиле с закрытым портом, показал неподтверждённый маршрут, автоматически выбрал ранее рабочий профиль и показал успешное подключение. В OverSecure наблюдалась смена отображаемого профиля при подключении. Причина этой смены и идентичный управляемый отказ в OverSecure недоступны через интерфейс эталона. |
| Отмена подключения и задержка | Во время подключения к тестовому недоступному узлу повторное нажатие кнопки отменило операцию. Терминал показал `VPN connection canceled`, TUN закрылся. Отдельная проверка задержки рабочего профиля вернула числовой результат через Xray. |
| Выключение и возврат Wi‑Fi | На совпадающем профиле TUN остался у обоих клиентов, после возврата Wi‑Fi отдельное приложение снова получило HTTP 204. При первом прогоне OverSecure на составном профиле ответ в отведённое окно не получен. |
| Wi‑Fi ↔ мобильная сеть | Телефон сообщил `ABSENT,ABSENT` для SIM. Переключение на мобильный транспорт осталось проверкой по коду. |
| Счётчики и плитка | Phantom показал накопленные байты после реального трафика. Плитка Phantom подняла TUN и отключила его. Тестовую плитку удалили по окончании проверки. |
| Завершение и повторный запуск процесса | В обоих клиентах `force-stop` убрал TUN. После ручного запуска сохранился выбранный профиль. Самопроизвольное завершение процесса системой и режим Android Always-on отдельно не воспроизводились. |
| IPv6 | Оба клиента установили маршрут `::/0` на `tun0`. С включённой настройкой Phantom также создал IPv6-адрес. HTTPS-запрос на один IPv6-литерал через совпадающий профиль завершился ошибкой в обоих клиентах. Сквозной IPv6-трафик на этом узле не подтверждён. |
| IPv4, DNS и UDP | В Phantom Android объявил оба DNS-адреса. В обоих клиентах прямой UDP-запрос к `1.1.1.1:53` получил `RCODE 0` и восемь ответов. HTTPS по имени с другого UID также прошёл. Проверка утечек DNS требует наблюдения на физическом канале. В этом прогоне проверены настройки DNS и ответ на запрос. |
| Фильтрация приложений | На Honor выбран один разрешённый пакет. Контрольный UID отсутствовал в диапазоне UIDs VPN. Аппаратная проверка режима исключений и сравнение фильтров OverSecure остались за пределами прогона. |
| Импорт и обновление | После исправления распознавания `Https://` Phantom получил 80 профилей через `/fetch`. При ручном обновлении изменились отметка времени и файл зашифрованного каталога, размер списка остался 80. Без Wi‑Fi обновление вернуло ошибку разрешения имени, и все 80 профилей сохранились. После возврата Wi‑Fi обновление прошло. OverSecure после повторного сохранения URL подключил прежний профиль. Успешный переход на резервный хост остался проверкой по коду, поскольку основной и резервный адреса отключались одновременно при потере сети. |
| Экран Phantom | На снимках главная панель, терминал, кнопка, цвета, типографика и иконки совпадают. Блок профиля отражал разные сохранённые данные двух установок. |

Задержки фонового мониторинга, лимит переключений, остановка при отзыве разрешения, действие уведомления и обход приложений подтверждены исходниками. В Honor панель показывала свёрнутое уведомление Phantom, поэтому нажатие его действия осталось непроверенным. Испытание на Honor охватило одно автоматическое переключение, а лимит рассчитан на пять. Состояние Dozing проверено на коротком интервале без длительного цикла энергосбережения.

Сборка, lint и 13 обычных unit-тестов прошли. Отдельный опциональный тест передал 80 профилей из POST в настольный Xray `run -test` после подготовки конфигурации Phantom. Отклонённых профилей было 0. Оба APK прошли проверку подписи и 16 КБ выравнивания, тестовый токен отсутствует в содержимом APK.

На телефоне установлена проверочная сборка `app.phantom.verification`. У исходной установленной Phantom 1.0.4 другой сертификат. Подписанный APK с обычным идентификатором `app.phantom` собран для установок с совместимым сертификатом. Изменения Wi‑Fi и мобильных данных возвращены к исходным значениям.
